# hoje-output

Claude Code의 응답 형식을 정규화하는 output style입니다. 내장 `Proactive` 스타일을 베이스로 삼아 자율 실행 성향은 유지하고, 응답 길이와 구조만 조입니다.

## 무엇이 달라지나

- 서론과 맺음말 없이 결론부터 시작합니다.
- 최종 답변은 불릿 두세 개, 전체 200자 내외로 제한됩니다. 불릿 하나가 두 문장을 넘지 않습니다.
- 이미 `Edit`나 `Write`로 파일에 쓴 코드를 답변에 다시 붙이지 않고 `경로:줄번호`로만 가리킵니다.
- 클래스명·메서드명·변수명은 사용자가 그것으로 무언가를 찾거나 실행하거나 판단해야 할 때만 등장합니다.
- 요청하지 않은 대안, 트레이드오프, 후속 작업 제안이 붙지 않습니다.
- 이모지와 `좋은 질문입니다` 같은 정보 없는 상투구를 쓰지 않습니다.

## 분량 제한이 풀리는 경우

사용자에게 선택이나 승인을 요청하는 답변에는 200자 제한을 적용하지 않습니다. 선택지와 각 선택지의 결과, 판단에 필요한 사실을 분량 때문에 잘라내면 안 되기 때문입니다. 이때는 `AskUserQuestion` 도구로 묻고, 선택지가 다섯 개를 넘어 도구에 담기지 않을 때만 본문에 나열합니다.

## 유지되는 것

`keep-coding-instructions: true`로 선언되어 있어 Claude Code의 기본 코딩 지시가 시스템 프롬프트에 그대로 남습니다. 보안 취약점 회피, 주석 작성 규칙, 불필요한 추상화 금지 같은 지시가 사라지지 않습니다.

내장 `Proactive`의 실행 규칙 여섯 개도 원문 그대로 들어 있습니다. 파괴적 작업 전 확인과 데이터 유출 방지 조항이 여기 포함됩니다. `TaskCreate`로 작업을 추적하는 것은 plan mode가 아니므로 즉시 실행 성향과 충돌하지 않습니다.

## 언어

한국어 응답 전용 규칙과 `~했습니다` 완료 보고 어미 규칙이 들어 있습니다. 한국어로 작업하는 사용자를 위한 스타일입니다.

## 사용법

플러그인을 활성화하면 자동으로 적용됩니다. `force-for-plugin` 이 켜져 있어 `/output-style` 에서 따로 고르지 않아도 됩니다. 반대로 그 환경에서는 다른 output style로 바꿀 수 없으니, 스타일을 골라 쓰고 싶다면 플러그인을 끄고 아래 방법을 쓰세요.

`~/.claude/output-styles/` 에 같은 이름의 파일을 직접 두면 그쪽이 플러그인 버전보다 우선합니다. 규칙을 손봐서 쓰고 싶을 때 활용하세요.
